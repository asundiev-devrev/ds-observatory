Stream 01 — Visual refresh

Froze, redefined,
now untangling.

A token-bleed incident in early June forced a freeze: applying Arcade values on top of an unaligned token base was breaking production. We restored the DevRev palette, then defined what the refresh actually is — updating token values on components that share one set of tokens and class names.

The work now is the foundation: align tokens across themes so a single change behaves predictably, then wire components to it. Real changes follow once the base is safe.

Where it's hard

Visual refresh paused to fix the foundation first.

Recurring visual regressions — some at incident level, with customer reports surfacing months late — exposed deep token fragility. The system has no fallbacks, so when a token breaks, it breaks hard (e.g. ADS-449, a missing tickets-list indicator dot).

The call: stop layering more themes on an unstable base. Untangle the control-token architecture so a single token change behaves predictably across every theme and mode — then resume the refresh.

  • Quality controlEnd-to-end self-QA before every PR
  • Visual regressionVRT live · ~6k stories in <7 min · captures being fixed
  • CI integrationRequirements doc in progress — next step
  • Token untangleControl tokens first, then parallelize
